# 01 Product Vision

## Long-term vision

Create an African-focused cloud infrastructure platform that lets developers and businesses provision computing resources, deploy applications, store data, connect services, monitor workloads, and control infrastructure without dealing directly with physical servers.

## Customer promise

The customer experience should eventually feel simple:

Connect a code repository -> choose an environment -> deploy -> monitor -> scale.

Underneath that simple experience, the platform manages virtualization, networking, storage, scheduling, security, capacity, billing, and recovery.

## Initial customers

The first practical customer groups are:

- independent developers
- software agencies
- early-stage startups
- small businesses with web applications
- teams that need affordable development and staging environments

## Initial market position

The platform should initially compete on simplicity, developer experience, support, local or regional hosting options, and transparent pricing rather than trying to win on sheer infrastructure scale.

## Service ladder

### Layer 1: Compute

Virtual machines with configurable CPU, memory, disk, operating system images, private networking, and optional public networking.

### Layer 2: Storage

Persistent block storage first. Object storage can follow once the storage foundation is stable.

### Layer 3: Networking

Private networks, subnets, firewall rules, public addresses, routing, and eventually load balancing.

### Layer 4: Developer deployment

Container-based deployments and Git-based workflows after the virtual machine platform is reliable.

### Layer 5: Managed services

Managed PostgreSQL, Redis-compatible caching, object storage, backups, and additional services based on actual demand.

## Product differentiation to investigate

- African region and support options
- simple local-currency billing
- developer-first deployment experience
- transparent resource limits
- predictable performance classes
- optional managed infrastructure for small teams
- strong onboarding and technical support

These are hypotheses, not yet validated claims. Customer discovery must determine which matter most.
